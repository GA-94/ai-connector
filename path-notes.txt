Десктопный ассистент: Python + PyQt, ИИ-агент с доступом к файлам проекта.

Версии

0.0.1 Alpha: подключение внешних моделей по API-ключу.
0.0.2 Alpha: инструменты CRUD, настройка API-ключа.
0.1.0 Alpha: GUI на PyQt5, стартеры main.pyw и start.pyw, первые тесты.
0.1.1 Alpha: отдельные настройки чатов.

0.2.0 Alpha (сделано за вечер):
- рабочее пространство из нескольких проектов: основной + добавленные папки,
  разбор путей вида "имя:src/File.java", "repo:...", проверка на zip-slip;
- склад шаблонов: repo_list, repo_search, repo_archive_list, repo_read_file,
  repo_import_file, repo_extract, repo_fetch;
- мягкое удаление: deactivate_file (*.deactivated) и backup_and_remove_dir
  (сначала zip-копия, потом удаление папки);
- java-инструменты и java_parse_log, чтобы агент читал вывод Gradle напрямую.

0.3.0 Alpha:
- ключ API вынесен из папки программы: %APPDATA%\AI-Connector\secrets.ini
  или ~/.config/AI-Connector/secrets.ini, переопределение через
  AI_CONNECTOR_API_KEY / AI_CONNECTOR_SECRETS, ключ маскируется в чате, консоли и логах;
- python_info и python_run для агента: инлайн-код или скрипт проекта,
  рабочая папка = корень проекта, ограничение по времени;
- repo_status объясняет, чего не хватает складу; панель репозитория умеет скачать
  архив по ссылке, переименовать, править, распаковать в проект, удалить в _trash/;
- счётчик расходов на чат.

0.4.0: баланс провайдера через RouterAI credits API, кнопка «Баланс» в главном окне,
  остаток попадает в системный промпт, инструмент account_balance, режим экономии
  ниже порога.
0.4.1:
- темы dark / midnight / light, картинка-фон, полупрозрачные панели (glass);
- у каждой темы свой набор цветов для чата и подсветки кода;
- ответы рендерятся в Markdown с подсветкой (pygments), сообщения в карточках,
  HTML из ответа модели не исполняется;
- карточки: «Вы» синим, «AI» зелёным, плашка целиком одной таблицей — иначе
  форматирование рвётся на блоках кода.

0.5.0-0.5.3 (самый долгий заход, папка переименовывалась по ходу 0.5.0 -> 0.5.3):
- список провайдеров (RouterAI, OpenAI, xAI, Gemini, DeepSeek, Mistral, OpenRouter,
  локальная Ollama), окно провайдеров, у каждого свой адрес, ключ и модель;
- клиент Ollama на /api/chat с num_ctx и num_gpu, выбор «видеокарта / оперативка / авто»,
  проверка загруженной модели через /api/ps;
- определение железа, подбор моделей под него, скачивание модели с прогрессом;
- стоимость запроса в рублях и учёт токенов (pricing.py);
- git: коммит и публикация на GitHub, токен из настроек и вырезается из логов;
- менеджер инструментов: включение группами и по одному;
- архив чатов: скрытые диалоги можно вернуть или удалить насовсем;
- своя полоса заголовка в цветах темы вместо системной рамки, перетаскивание и
  изменение размера по краям, отдельная ветка для Wayland;
- app/img (minus/cvadrat/crest) в кнопках окна, перекраска под тему,
  без файла — откат на текстовый символ;
- запуск на Linux: start.sh, start_linux.py, runtime_env.py (нормализация путей,
  ^M, сведения об ОС в промпте агента);
- импорт базы чатов с проверкой схемы и бэкапом в data/backups/;
- настройки разложены по 8 вкладкам, окно настроек чата в две колонки
  и с подгонкой под экран (dialog_fit);
- поле ввода на 1-8 строк, Enter отправляет, Shift+Enter переносит строку;
- отладчик GUI по F12.

0.6.0-0.6.2 (пять доработок, часть заходов упиралась в лимит итераций агента):
- тумблер скрытия кнопок окна (конфликтуют с тайловыми менеджерами);
- верхняя панель: название и версия сверху, кнопки действий ниже в рамках,
  прозрачный фон панели, тумблер «показывать фон» в меню «Вид»;
- краш-репорты в crash_reports рядом с программой: исключения Python, потоки,
  qFatal, faulthandler для жёстких падений;
- склад: выбранный файл копируется в папку склада, внешний сначала скачивается
  (repo_fetch) и только потом распаковывается в проект;
- свои инструменты ИИ (python и shell) в data/custom_tools.json: создание, правка,
  запуск, разрешение задаётся в настройках чата;
- генератор «Создать с ИИ…» — по описанию модель предлагает готовое определение
  инструмента, плюс галочка «Разрешить ИИ изменять, добавлять, удалять инструменты»;
- в поставку временно входил шаблон мода Minecraft (MDK: gradle-проект, ExampleMod).

0.6.3:
- вычищен java-мусор из папки программы (build.gradle, gradle.properties, gradlew,
  gradle/, src/ от Forge MDK, forge-чейнджлог), бэкап в data/backups/java_junk_*.zip;
- починен баг «в случайный момент не отправляется следующее сообщение»: выбор чата
  висел на клике мышью (itemClicked), а current_session сбрасывался из нескольких мест.
  Теперь ловим currentItemChanged, чат открывается программно, плюс сторож кнопки
  «Отправить» с таймером 1.5 с;
- служебные строки ([ERROR 429]…, «Отменено пользователем», пустые) больше не уходят
  обратно модели как её предыдущий ответ;
- .gitignore переписан под Python.

0.6.4:
- сторож интерпретатора (interp_guard) — защита от free-threaded сборки Python 3.13+/3.14t,
  на которой PyQt5 падает без traceback;
- safe_app: QApplication, который не падает от исключения в обработчике интерфейса;
- учёт фоновых QThread и корректный выход из программы;
- журнал запуска boot.log, стартер start_debug.py, кэш интерпретатора
  data/interp_cache.json;
- запуск без IDE: стартер сам находит подходящий python и перезапускает программу.

0.7.0:
- удалённый доступ: SSH-терминал (интерактивный shell, свой cwd у сессии,
  маркер для кода возврата) и файловые хранилища SFTP/SCP/FTP(S)/SMB/S3/WebDAV
  с общим набором операций (list/download/upload/mkdir/rename/delete/stat);
- 12 инструментов агента: remote_terminal_list/open/exec/close,
  remote_storage_list/ls/download/upload/mkdir/rename/delete/info;
  у выключенного подключения схемы вообще не уходят модели;
- профили подключений у каждого чата свои; в базе чатов только адрес, порт и логин,
  пароли и ключи — в реестре Windows (HKCU\Software\Ai-Connector7\RemoteSecrets)
  или в файле конфигов Linux с правами 0600; удаление по одному или всех сразу;
- окна: редактор подключения, список подключений чата, менеджер паролей,
  отдельное окно терминала; docs/requirements-remote.txt;
- тесты: SSH к тестовому серверу — работает, FTP и SFTP (test.rebex.net) — работают,
  SMB, S3 и WebDAV остались без проверки, серверов с учётками не было;
- ограничение: оболочка одна на чат, два параллельных remote_terminal_exec
  сталкиваются и вешают шелл — команды гонять по одной.

0.8.0 ARM Edition Beta: облегчённая сборка, только read_file, write_file, edit_file
  и list_files, без java/python/склада/удалённого доступа, свои имена настроек
  (AiConnectorARM). Код переписан с нуля (20 .py), это не апгрейд 0.7.0.
- здесь же починен лимит итераций: интерфейс жёстко подставлял 15, в базе поля не было.
  Теперь sessions.max_iterations, по умолчанию 200, допустимо 3-1000, с авто-миграцией.

0.8.1 ARM Edition Beta: 0.7.0 на PyQt6 — PyQt5 не собирается под win_arm64.
- requirements: PyQt6>=6.7;
- пакет app/qt_compat/ — PyQt6 внутри, но с «плоскими» именами (Qt.AlignLeft,
  QAction и QShortcut в QtWidgets, QRegExp, QDesktopWidget), чтобы код 0.7.0
  переносился построчно;
- interp_guard и runtime_env знают архитектуру (architecture()/is_arm()), она уходит
  в промпт агента и в --diagnose, подсказки по PyQt6 для apt/pacman/dnf/zypper;
- после переезда часть кнопок не прожималась, чинилось отдельно.

0.8.2-beta (папка Ai-Connector-8, пакет aic8) — параллельная ветка, отменена:
  переписывание 0.7.0 на Python 3.15 + PyQt6 (AgentConfig вместо десятков аргументов,
  AgentError вместо строк «[ERROR …]», 43 схемы инструментов, свой markdown, свои диалоги).
  Интерфейс потом переделали под стиль 0.7.0, но в итоге вернулись к миграции живого
  кода 0.7.0 (см. 0.8.1). В репозитории осталась как project/Ai-Connector-8.

0.8.3 (папка Ai-Connector_v0.8.2, в коде версия 0.8.3): продолжение линии 0.7.0 на PyQt6.
- поиск по смыслу: semantic_search на эмбеддингах Ollama (/api/embed), индекс
  кэшируется на диск;
- ollama_service: поиск установки, запуск и перезапуск, OLLAMA_CONTEXT_LENGTH,
  OLLAMA_KEEP_ALIVE, OLLAMA_HOST, автозапуск вместе с программой;
- быстрый режим: у Ollama think=false, у облачных моделей понижено усилие
  рассуждений, настройка запоминается для чата;
- счётчик токенов контекста вместо баланса для локальных моделей (token_widget);
- фоновые опросы model_probe, окна больше не подвисают на 10-15 с;
- предупреждения агенту, если Ollama выбросила параметр tools или контекст меньше
  схем инструментов (иначе модель сообщает о созданном файле, которого нет);
- данные разнесены по профилю: app.db (чаты и настройки) и secrets.db (ключи,
  токен GitHub, пароли и адреса подключений);
- импорт базы чатов с бэкапами, миграция данных прежних версий в профиль.

0.8.4:
- разделение данных отыграно назад: настройки в settings.ini (QSettings),
  база чатов в data/chats.db рядом с программой, ключ API — в secrets.ini в профиле
  (%APPDATA%\AI-Connector\ или ~/.config/AI-Connector/, путь переопределяется
  AI_CONNECTOR_SECRETS);
- из кода убраны config/kvstore.py, config/paths.py, config/secrets_db.py,
  вместо них config/settings.py, config/chat_store.py, config/secrets.py;
- база чатов привязана к папке программы, запуск из другого каталога больше не плодит
  пустые data/chats.db, замена базы с копией в data/backups/;
- профили удалённых подключений лежат в базе чатов, пароли по-прежнему в реестре
  Windows или в файле конфигов Linux;
- crash_reports рядом с программой, туда же пишут мост Qt и сторож интерпретатора;
- окно настроек показывает реальные пути (settings.ini, база чатов, secrets.ini)
  и открывает папку программы и папку data;
- тесты удалённого доступа перенесены в tests/.


Починенные проблемы (по датам правок)

- 01.11: агент дважды встал на «Достигнут лимит итераций вызова инструментов».
  Отсюда настройка лимита на чат в 0.8.0 и кнопка «Стоп» в 0.6.3.
- 04.11: не отправлялось следующее сообщение. Лечение в 0.6.3 — currentItemChanged,
  сторож кнопки, фильтр служебных реплик.
- 08.11: пустые краш-репорты и запуск только из VS Code. Лечение в 0.6.4 —
  boot.log, safe_app, interp_guard, учёт QThread.
- 12.11: 429 monthly spending limit — ограничение в кабинете провайдера,
  не в программе.
- 14.11: в настройках чата оставалось 15 итераций. Реально чинилось со второго захода,
  ломалось на хардкодах в main_window.py и chat_settings_dialog.py.
- 14.11: после переезда на PyQt6 часть кнопок не прожималась, разбирали отдельным заходом.
- 14.11: часть заходов по 0.8.1 оборвалась на лимите баланса и итераций, доделывалось
  следующим сообщением.
- 31.10: ForgeGradle падал на кириллице в пути пользователя (C:\Users\<имя>),
  лечится GRADLE_USER_HOME на ASCII-путь. Полезно помнить.
